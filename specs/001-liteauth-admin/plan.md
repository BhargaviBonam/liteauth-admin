# Implementation Plan: LiteAuth Admin

**Branch**: `001-liteauth-admin` | **Date**: 2026-05-26 | **Spec**: [spec.md](./spec.md)

## Summary

Build a full-stack SaaS-style admin dashboard that handles JWT authentication, RBAC, user/task management, activity logging, and analytics — using React + Shadcn UI on the frontend and Node.js + Express + SQLite on the backend.

## Technical Context

**Language/Version**: TypeScript 5.x (frontend + backend), Node.js 20 LTS

**Primary Dependencies**:
- Frontend: React 18, Vite, Tailwind CSS, Shadcn UI, Lucide Icons, Recharts, React Router v6, React Hook Form, Zod, Axios
- Backend: Express 4, better-sqlite3, jsonwebtoken, bcrypt, express-validator, cors, cookie-parser, multer (avatar upload)

**Storage**: SQLite via better-sqlite3 (file: `server/database/liteauth.db`)

**Testing**: Manual API testing via curl/Postman; component-level visual verification

**Target Platform**: Local development (Linux/Mac/Windows); accessible at `http://localhost:5173` (frontend) and `http://localhost:3001` (backend)

**Project Type**: Full-stack web application (SPA frontend + REST API backend)

**Performance Goals**: All list pages < 2s load time locally; JWT validation < 10ms per request

**Constraints**: SQLite limitations accepted for v1; no external services (email, blob storage); single-tenant

**Scale/Scope**: ~5 pages with CRUD + auth; seed data for demo flow; ~15 API endpoints

## Constitution Check

- ✅ **Principle I (Component-First)**: All UI will use functional React components, Shadcn UI, Tailwind CSS, Lucide Icons, TypeScript.
- ✅ **Principle II (Secure by Default)**: JWT middleware on all non-login routes, bcrypt hashing, express-validator, httpOnly cookies.
- ✅ **Principle III (RBAC)**: Permission matrix defined, server-side enforcement, declarative middleware.
- ✅ **Principle IV (REST Conventions)**: Express Router per domain, standard HTTP verbs + status codes, `{ data, error, meta }` envelope.
- ✅ **Principle V (Activity Audit)**: Every CRUD action and auth event logs to `activity_logs`.

## API Contracts Summary

| Method | Endpoint | Auth | Role | Description |
|--------|----------|------|------|-------------|
| POST | /api/auth/login | No | Any | Login, return JWT |
| POST | /api/auth/logout | Yes | Any | Clear session |
| GET | /api/auth/me | Yes | Any | Get current user |
| GET | /api/users | Yes | Admin+ | List users (paginated) |
| POST | /api/users | Yes | Admin+ | Create user |
| GET | /api/users/:id | Yes | Admin+ | Get single user |
| PUT | /api/users/:id | Yes | Admin+ | Update user |
| DELETE | /api/users/:id | Yes | Admin+ | Delete user |
| PATCH | /api/users/:id/status | Yes | Admin+ | Toggle active |
| GET | /api/tasks | Yes | Manager+ | List tasks |
| POST | /api/tasks | Yes | Manager+ | Create task |
| PUT | /api/tasks/:id | Yes | Manager+ | Update task |
| DELETE | /api/tasks/:id | Yes | Admin+ | Delete task |
| GET | /api/roles | Yes | Admin+ | List roles + permissions |
| PUT | /api/roles/:role/permissions | Yes | Super Admin | Update role permissions |
| GET | /api/activity-logs | Yes | Admin+ | List activity logs |
| GET | /api/dashboard/stats | Yes | Any | Dashboard stat counts |
| PUT | /api/profile | Yes | Any | Update own profile |
| POST | /api/profile/avatar | Yes | Any | Upload avatar |
